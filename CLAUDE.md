# sk-santhosh.info

Personal portfolio as a Next.js **static site** deployed to Vercel on the
custom domain `https://sk-santhosh.info` (served at the root).

## Architecture

- Next.js App Router under `src/app`, `output: "export"` — every route
  prerenders at build time and the whole site ships as static files in `out/`.
  There is no server at runtime, so any route handler or metadata route needs
  `export const dynamic = "force-static"`.
- Content is markdown under `content/` — `projects/` and `blogs/` — read by
  `src/lib/content.ts` at build time. Code is highlighted by Shiki with VS
  Code's Dark+ theme, so no highlighter ships to the browser.
- Site copy that isn't markdown lives in `src/data/content.ts`.
- Open Graph cards are generated per route by `opengraph-image.tsx` files
  sharing `src/app/_og/card.tsx`; fonts and images are read off disk so the
  cards render at build time without network access.
- `images: { unoptimized: true }` — a static export has no image optimiser at
  runtime, so `<Image>` must emit the files as they are.
- `basePath` is empty for the custom-domain (root) deployment, but is wired to
  `NEXT_PUBLIC_BASE_PATH` so a sub-path build needs no code changes.

## SEO

- `robots.ts`, `sitemap.ts` and `manifest.ts` are Next metadata routes.
- `rss.xml/route.ts` and `llms.txt/route.ts` build the feed and the
  answer-engine site guide from the same content the pages render, so neither
  can drift from the markdown. Nothing is generated by a script or committed.
- JSON-LD is one entity graph: the layout declares `Person` and `WebSite` with
  stable `@id`s, and per-page schema (`BlogPosting`, `BreadcrumbList`)
  references them rather than redeclaring the author.
- The absolute origin comes from `src/lib/seo.ts`, not a hardcoded constant, so
  preview and sub-path builds describe themselves correctly.

## Deployment

Hosted on Vercel with its Git integration: every push to `master` triggers
`npm run build` and a deploy. Vercel auto-detects Next.js with
`output: "export"` and serves `out/`, so there is no `vercel.json`. The custom
domain is configured in the Vercel dashboard (Project → Settings → Domains).

Environment variables are set in Vercel (Project → Settings → Environment
Variables), not in the repo — all are optional and the build is correct
without them:

- `NEXT_PUBLIC_SITE_URL` — overrides the absolute origin used for canonical
  URLs, the sitemap, robots and the feeds.
- `NEXT_PUBLIC_BASE_PATH` — serve the site under a sub-path.
- `NEXT_PUBLIC_GA_ID` — GA4 measurement ID (`G-XXXXXXXXXX`); when unset, GA is
  not loaded, so local traffic never reaches analytics.
- `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` — Search Console HTML-tag token (DNS
  verification is already in place, so usually unneeded).
